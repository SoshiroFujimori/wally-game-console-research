# 用語を理解の入口にする

[分野別の入口](README.md) · [一つの四角形を追う](walkthrough.md)

## 1 値を表す言葉

| 用語 | この資料での意味と具体例 |
|---|---|
| ビット | 0か1の一つの値。8ビットを並べれば256通りの組合せがある |
| バイト | 8ビット。メモリの番地や転送量はバイト単位で数えることが多い |
| 語 | まとめて扱う値の単位。CPUが64ビットでも、今回の描画命令入力の一語は32ビットである。必ず幅を確認する |
| 符号付き整数 | 負の値も表せる整数。8ビット二の補数の`11111111`は−1であり、符号なしなら255になる |
| 固定小数点 | 整数を一定の倍率で解釈して小数を表す方法。小数部5ビットなら整数48を`48/32=1.5`と読む |
| オフセット | 基準からの差。`0x10080000`を基準に`0x0C`バイト先なら`0x1008000C`である |
| ビット幅 | 保存や計算に使える桁数。結果が幅に入らないと、上位の桁が失われる場合がある |

数値の型によって同じビット列の意味が変わる点は、[RTL](logic-rtl.md)と[画素計算](rasterization.md)で確かめる。

<a id="sec-2"></a>
## 2 回路を表す言葉

| 用語 | この資料での意味と具体例 |
|---|---|
| 論理ゲート | 入力の0/1から出力の0/1を決める基本的な回路。ANDなど |
| 組合せ回路 | 現在の入力から出力を決める回路。加算や値の選択など。実物には伝わる時間がある |
| FF | クロックの立ち上がりなどで一ビットを保存する回路。前に保存した値を次の保存時点まで保つ |
| レジスタ | 値を保持する場所。CPU内部の汎用レジスタと、周辺機器の制御用レジスタでは使い方が違う |
| クロック | 回路が値を保存する時点の基準となる周期信号。一周期で必ずCPUの一命令が完了するとは限らない |
| RTL | レジスタ間でどんな値を計算し、いつ保存するかという粒度の回路記述。HDLのすべての文が同じ種類の回路になるわけではない |
| 論理合成 | HDLから、利用する論理機能や記憶素子の接続を求める処理。プログラムをCPUの機械語へコンパイルする処理とは異なる |
| 配置配線 | FPGA内部のどこへ機能を置き、どの配線で結ぶかを決める処理 |
| LUT | 少数の入力の組合せに対する出力を設定して、論理関数を実現するFPGAの資源 |
| BRAM | FPGA内のまとまった記憶資源。HDLで配列を書けば、どんな読み書き方法でも必ずBRAMになるわけではない |
| DSP | 積和などに利用できる専用の演算資源。ゲームの音声処理専用という意味ではない |
| ビットストリーム | FPGAの回路構成を設定するためのデータ。ゲームの実行ファイルとは別に作る |
| IP | 再利用できる回路の部品や設計。ここではインターネットの番地を指すIPとは別の意味 |
| MIG | 外部メモリを操作する回路を生成するAMDの仕組み。基板のメモリや配線に合わせた設定を使う |
| MMCM / PLL | 基準クロックから必要な周期や位相のクロックを作るための回路資源 |
| SoC | CPUとメモリへの接続、周辺機器の制御などをまとめたシステム。CPUの計算部分だけを指す言葉ではない |

回路としての意味は[RTL](logic-rtl.md)、実装結果の読み方は[FPGAの時間条件](timing-fpga.md)を使う。

<a id="sec-3"></a>
## 3 接続と待機を表す言葉

| 用語 | この資料での意味と具体例 |
|---|---|
| バス | 複数の機能間でアクセスを行う接続と規則。単に一本の線という意味ではない |
| APB | 番地を指定して周辺機器を読み書きするバスの規則。`PREADY`によって完了を待たせられる |
| AXI4-Stream | 語を順に渡すための規則。今回の命令入力では番地を各語と一緒に渡さない |
| ready / valid | 受取り可能か、有効な値を提示しているかを表す信号。同じ立ち上がりで両方が1なら受理する |
| バックプレッシャー | 受け側が一時停止を送り側へ伝えること。FIFOという部品の名前ではない |
| FIFO | 先に保存した語から取り出す記憶構造。満杯なら新しい語の受付けを待たせる |
| CDC | クロックの領域をまたいで情報を渡す設計上の問題や処理。FIFOだけを指す言葉ではない |
| 非同期FIFO | 入口と出口を別のクロックで扱うFIFO。二つのクロックを同じ周波数へ変換する装置ではない |
| メタステーブル | 保存するタイミングの条件を満たさないと、FFの出力が通常より長く不安定になる現象 |
| 同期器 | 別のクロック領域から来た信号を受けるための回路。多ビットを個別に通すだけでは値のまとまりを保証できない |
| ハンドシェイク | 要求、受取り、確認などの条件を決めてデータを渡す手順。一語保持のCDCにも使える |
| 所有権 | その保存場所を、いま誰が書き換えてよいかという取り決め。読み手が使う前に送り手が再利用してはいけない |

これらは[APBとクロック間接続](cdc-protocols.md)で、一語の値を時系列で追って説明する。

<a id="sec-4"></a>
## 4 CPUとLinuxを表す言葉

| 用語 | この資料での意味と具体例 |
|---|---|
| ISA | 命令がどのように動作するかなど、CPUとソフトウェアの間の仕様。RISC-Vはその一つ |
| マイクロアーキテクチャ | ISAをどういう内部回路で実現するか。段数、キャッシュ、演算器など |
| パイプライン | 命令処理を段に分け、異なる命令の処理を重ねる構成。一つの命令の依存関係が消えるわけではない |
| ストール | 待つ必要があるため、ある段が次へ進まないこと |
| フラッシュ | 分岐などで不要になった処理を無効にすること。キャッシュをメモリへ書き戻す操作と混同しない |
| キャッシュ | よく使うメモリの内容をCPUの近くへ保持する仕組み。元のメモリと異なる値が一時的に存在する条件もある |
| MMU | 仮想番地から物理番地への変換やアクセス権の確認を行う仕組み |
| TLB | 番地変換の情報を覚えておく場所。プログラムのデータそのものを覚えるデータキャッシュとは違う |
| MMIO | 番地への読み書きを周辺回路の操作に使う方法。読み出すこと自体が機器の状態を変えるレジスタもある |
| DMA | CPUがデータを一語ずつコピーする代わりに、転送回路がメモリを読み書きする仕組み |
| ABI | 関数の引数、戻り値、レジスタの使い分けなど、コンパイルした部品を組み合わせるための取り決め |
| ELF | Linuxなどで使う実行ファイルの形式。命令やデータ、ロードに必要な情報を格納する |
| デバイスツリー | 機器の番地など、ボードの構成をソフトウェアへ伝える記述。HDLを書き換える機能ではない |
| 割込み | 機器などがCPUへ処理を促す通知。ポーリングのようにCPUが状態を何度も読む方法とは異なる |
| フェンス | メモリアクセス等の順序に制約を与える命令。必要なキャッシュ管理まで何でも代行する命令ではない |

命令の進み方は[CPU](cpu.md)、番地とキャッシュは[メモリ](memory-bus.md)、実行環境は[Linux](linux.md)で詳しく扱う。

## 5 図形と画像を表す言葉

| 用語 | この資料での意味と具体例 |
|---|---|
| 頂点 | 図形を定める位置などの情報。位置以外に色やテクスチャ座標を持つこともある |
| ラスタライズ | 図形から、処理対象にする画素の位置などを求めること |
| フラグメント | 図形から得られた、ある画素位置に対応する色などの処理候補。後段で捨てられ、画像へ書かれない場合もある |
| 補間 | 頂点などに与えた値から、その間の位置の値を求める計算 |
| テクスチャ | 描画時に色などを取り出すための画像。文字の形も保存できる |
| アルファ | 色を混ぜる割合などに使う値。使い方は描画設定による |
| ブレンド | 新しく描く色と、保存されている色を式に従って混ぜる処理 |
| フレームバッファ | 画素の色などを保存する画像領域。描画命令を保存するコマンドバッファとは違う |
| フロント／バック | 表示中／次の描画先という画像領域の役割。切り替えると役割も交代する |
| RasterIX_IF | 内部のフレームバッファを利用するRasterIXの構成。表示用DDR画像の二枚組と同じものではない |
| スキャンアウト | 保存した画像を表示の順番とタイミングで読み出すこと |
| ティアリング | 表示している途中で画像の状態が変わり、一画面に異なる更新の部分が混ざる現象 |
| 変更領域 | 前回の画像から変える必要がある範囲。物体を消した跡に重なっていた背景も復元が必要になる |
| VBO | 頂点データをバッファとして扱うAPI上の仕組み。利用すればこの構成の全ボトルネックが消えるとは限らない |

図形から命令までは[コマンド](commands.md)、画素の計算は[ラスタライズ](rasterization.md)、保存と表示は[フレームバッファ](framebuffer-display.md)へ進む。

## 6 実験と検証を表す言葉

| 用語 | この資料での意味と具体例 |
|---|---|
| レイテンシ | ある開始から対応する完了までの時間。開始と完了の定義が必要 |
| スループット | 一定時間に完了した仕事の量。一つの仕事の所要時間の逆数と常に一致するわけではない |
| FPS | 一秒あたりのフレーム数。ゲーム更新、切替え完了、記録映像のどれを数えたかも必要 |
| 中央値 | 値を小さい順に並べた中央の値。平均値とは計算法が異なる |
| ベースライン | 比較の基準となる構成や処理方式。版や設定も固定する |
| オラクル | 正誤を判断するための期待結果や別の確認方法。比較相手も同じ誤りを持つ場合には注意が必要 |
| スコアボード | 入力から予想する出力を記録し、実際の出力と比較する検証用の仕組み |
| アサーション | 特定の条件が必ず成り立つべきだと記述する検査 |
| 形式検証 | 明示したモデルと前提の下で性質を数学的に調べる方法。普通の実機試験を行っただけで形式検証済みとは呼ばない |

数値の解釈は[計測](measurement.md)、確かめ方は[検証](verification.md)を使う。
