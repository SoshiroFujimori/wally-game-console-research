# ゲーム機を回路とプログラムから理解する詳説

[研究全体](../../README.md) · [論文と技術付録](../thesis/README.md) · [用語の入口](glossary.md) · [出典と対象版](sources.md)

CPUがボールの位置を変えてから、画面に新しいボールが映るまでには、計算、メモリへの保存、回路間の通信、画素の生成、画像の読出しがある。この詳説は、その途中を省略せずに理解するための資料である。**用語を知ることに加え、「どの値を、どの回路が、いつ受け取り、何が終われば次へ進めるのか」を説明できることを目標にする。**

既存の[技術付録](../thesis/技術付録.md)には、実装の詳細、ソースの所在、再現手順、検証記録を保存している。本詳説では、その理解に必要な前提と数値例を補う。既存付録を置き換えたり、実験結果を新しい説明用の数値へ置き換えたりするものではない。Word版にこの詳説の全内容を収録したという意味でもない。

## 一つの操作を全体に結び付ける

全体のつながりを先に確かめたい場合は、[白い四角形を一つ表示するまで](walkthrough.md)を読む。位置、頂点、命令、バスの一語、画素の色、表示の順に、「今あるもの」と「まだできていないもの」を区別している。

計算を自分で確かめたい場合は、[実行できる説明用モデル](../../examples/technical-models/README.md)を使える。Pythonの標準機能だけで、待機中のデータ保持、画素の座標、RGB565、クロック周期、キャッシュの対応を確認する。ボードもLinuxのディスクイメージも変更しない。これらのモデルを通したことと、FPGAの実装を検証したことは別である。

<a id="sec-3"></a>
## 何が理解できれば設計の説明になるか

例えば「FIFOを使った」とだけ答えられても、接続の理解はまだ確認できない。次の問いに、信号や保存場所を示して答えられるか確かめる。

1. 一語を受け取ったと数える条件は何か。
2. 受け手が止まったとき、値を保持する責任はどちらにあるか。
3. APBへの完了通知と、RasterIXでの処理完了は同じか。
4. クロックをまたぐ情報は何か。そのまとまりをどう保つか。
5. FIFOを使わない案は成立するか。実験では何が違ったか。

CPU、描画、Linuxについても同じように、名前ではなく「入力、保存される値、処理、出力、完了の条件」を追う。分からない項目があるときは、その項目の説明が足りていない可能性もある。読者が未知の専門用語を自力で補うことを前提にしないため、[用語の入口](glossary.md)から各分野へ戻れるようにした。

<a id="sec-4"></a>
## 説明と証拠の読み分け

本詳説では、四角形の座標や4語FIFOなどの**説明用の例**、固定コミットを読んで確認する**実装の事実**、保存した記録から再計算できる**実測結果**を区別する。例えば4語FIFOの図から、製品のFIFOが4語だと判断してはいけない。

また、公式RasterIXを更新すると、同じ名前の回路でも処理が変わることがある。三角形の共有辺の扱いは、その実例である。本文とE6の版を混ぜないため、[出典と対象版](sources.md)に読み分けをまとめた。

詳しく書くことは、未測定の性能や、未実装の機能まで保証することではない。検証済みの範囲と、一般原理として説明している範囲を見分けながら、実物のソースと記録へ戻れることを重視する。
