# 発表の要点

[スライドと発表原稿](中間発表_主要事項.md) / [技術付録](../thesis/技術付録.md)

この発表では、既存の教育用CPUと描画回路を接続し、ブロック崩しが動くゲーム機を製作したことを説明する。

## 2枚目：FPGAとは

まず背景です。FPGAボードは、SDカードスロットやDDRメモリなどを載せた基板です。基板上にはFPGAチップもあります。このチップ内に、周囲の部品を制御するデジタル回路を実装できます。図のように、回路をコードで記述して、チップ内に実装します。

<details>
<summary>詳しい説明と出典</summary>


FPGAは、コードで記述したデジタル回路をチップ内に実装できるデバイスである。CPUも、その方法で実装する回路の一つである。SDカードなどを実際に制御するにはそれぞれの制御回路が必要であり、AND回路はコードと回路の対応だけを示す。回路を記述するHDLと、CPUが実行するゲームのプログラムは、それぞれ作る対象が異なる。

## 3枚目：先行研究と教育現状

このように、FPGAのチップ上にCPUや描画回路を実装する先行研究があります。CPUの例がWally、描画回路の例がRasterIXです。描画回路と表示用の回路によって、HDMI端子から映像を出力できます。また、CPU設計を授業で扱う高専や大学もあります。例えば、久留米高専や広島大学では、回路やCPU設計の教科書がシラバスに挙げられています。

<details>
<summary>詳しい説明と出典</summary>


CPUの先行研究には、WallyのCPU・SoC、FPGA実装と教材を扱うASEE論文を挙げる。RasterIXについては公式の研究・開発成果として公開された回路・ソフトウェアと実装例を参照する。RasterIXに査読付き論文があるという主張ではない。図はFPGAに実装できる既存回路を例示したもので、同じボードにWallyとRasterIXを接続した先行研究を示すものではない。描画・表示の出典と本研究の接続部分は4枚目で区別する。

## 4枚目：本研究の概要

## 5枚目：ソフトウェアの概要

次に、ソフトウェアの概要です。Wallyを含む既存の構成では、回路ごとにアドレスを割り当て、プログラムからアクセスできます。今回の描画回路にも、アクセスするためのアドレスを割り当てました。そこに、描画の指示を意味する数値を書き込みます。図の例では、0x10080000というアドレスへの書込みです。この数値を接続回路が描画回路へ渡すことで、画像を描画し、HDMI端子から映像を出力できます。

<details>
<summary>詳しい説明と出典</summary>


C言語による書込みの概念例である。commandはCPU上のライブラリが用意した描画命令列の1語を表す。実際には、命令列の複数の語を順に送り、転送完了や表示切替の制御も行う。実行可能な完全な送信プログラムではなく、アドレスへの書込みと回路の操作の対応を示す。実装はvolatile付きの入出力アクセスを使う。接続回路のコマンド送信口は0x10080000である。描画・表示回路がDDR3上の画像を介して映像を出力するため、一度の書込みだけで画面全体が完成するという意味ではない。

## 6枚目：ハードウェア：アドレスの割当て

次に、ハードウェアの概要です。Wallyの周辺回路には、アドレスデコーダがあります。これは、CPUからのアドレスを調べ、そのアドレスに対応する回路のイネーブル信号を出す回路です。本研究では、この既存の仕組みの設定を変更し、描画回路用のアドレス領域を割り当てました。例えば0x10080000に書き込むと接続回路が選ばれ、描画命令の数値が渡ります。

<details>
<summary>詳しい説明と出典</summary>


Wallyの既存の外部APB領域を有効にし、描画接続回路へ接続している。アドレスデコーダのRTLを一から書いたという意味ではなく、その既存の領域選択機能と構成パラメータを利用した。図はCPUの書込みを、アドレス、書込みデータ、書込みイネーブル、接続先の選択に分けた概念図である。実際にはAHBからAPBへの変換や転送の段階があるが、この図では省略している。有効なアクセスでWE=1が書込み、WE=0が読出しを示す。読み出しデータの戻り経路は、書込みだけを説明するこの図では省略した。0x10080000〜0x100800FFは接続回路用の領域で、その中の0x10080000が描画命令の送信口である。アドレス下位のビットが、接続回路内でアクセスするレジスタを指定する。

CPU・バス・SDカード制御はWallyリポジトリ（CVW）の既存RTLを利用する。DDRメモリ制御はWallyリポジトリの生成・接続の仕組みを利用し、回路本体はAMD製MIG IPである。Nexys Video用の設定は本研究で追加した。標準構成の描画本体RasterIX_IFと表示本体dvi_framebufferは、同じ公式RasterIXリポジトリから取得する。表示本体はrtl/3rdParty/core_dvi_framebufferに同梱されたultraembedded由来の回路で、RasterIXの作者がすべて新規に設計したという意味ではない。バスから描画回路への変換、画面切替などの接続処理は本研究で追加した。本資料の実機動画は、RasterIX同梱の表示本体を利用する標準構成で取得した。表示本体そのものを本研究で新規設計したという主張ではない。

## 7枚目：ハードウェア：接続回路

CPUと描画回路の間には、通信方式とクロック周波数の違いがあります。そのため、両回路の間に用意した接続回路で、この違いに対応しました。CPU側の書込みを、描画回路側で受け取れる信号のやり取りに合わせます。また、異なるクロックの間でデータを渡すために、AMD製の回路を組み込みました。これによって、CPUから描画回路へ命令を渡せるようにしました。

<details>
<summary>詳しい説明と出典</summary>


CPU側のAPB書込みを、RasterIX側のAXI4-Streamに対応させる部分は本研究で追加したRTLである。描画命令そのものを別の命令に変える処理ではなく、データと受渡しの制御信号を対応させる。クロック間にはAMD製AXI4-Stream Data FIFOを非同期設定で使う。標準構成はCPU側20 MHz、描画側100 MHzである。FIFOの内部回路を独自に発明した、またはこの方式が最速だという主張はしない。形式に合わせる部分は追加したRTL、クロック間の受渡しはAMD製IPである。

## 8枚目：実行結果：FPGAの使用量

次に、実行結果です。まず、FPGA内部のリソースの使用量を示します。FPGAには、論理回路やメモリなど、実装に使える資源の数に上限があります。表は、Wallyの基本構成と、今回のゲーム機構成の使用率です。ゲーム機では、LUTが約50%、チップ内のBlock RAMが約59%でした。CPUや周辺制御、描画・表示を含む回路を、一つのFPGAに実装できました。

<details>
