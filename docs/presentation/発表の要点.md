# 発表の要点

[スライドと発表原稿](中間発表_主要事項.md) / [技術付録](../thesis/技術付録.md)

この発表の中心は、**既存のCPUと描画回路をつなぐ接続を実装し、ブロック崩しの動作を実機で確認したこと**である。接続方法を、Wallyの学習者が参照できる拡張例として公開する。

## 1. FPGAとCPUの関係

FPGAは、デジタル回路を実装できるチップである。今回は、その中にCPU、SD制御、描画回路などを実装した。CPUもFPGAの中に作った回路の一つである。

ゲームのプログラムは、そのCPUが実行する。回路を記述するHDLと、ゲームを進めるプログラムは、作る対象が異なる。

**質問例：なぜFPGAを使ったのか。**

> CPUと描画回路の接続を、回路として変更できるからです。今回の目的はWallyに周辺回路を加える拡張例を示すことなので、既存の回路コードを組み合わせて実装できるFPGAを使いました。

対応するスライド：2。

## 2. 教科書とのつながりと目的

『ディジタル回路設計とコンピュータアーキテクチャ』（DDCA）では、値を保存するレジスタ、加算などを行う演算回路、命令に応じて動作を指示する制御回路を組み合わせ、CPUを設計する。東京大学・広島大学・豊田高専・久留米高専などに教科書・教材の指定例がある。年度と版は学校によって異なる。

『RISC-V System-on-Chip Design』（RVSOC、スライドでは「RISC-V SoC設計」と表記）は、その基礎を発展させ、WallyのCPUや、メモリ・周辺回路への接続を学ぶ本である。第9章はバス接続、第20章は周辺回路、第23章はFPGA実装を扱う。Harvey Mudd Collegeとダルムシュタット工科大学で教科書指定を確認し、Oklahoma State Universityでは出版前の原稿を用いた授業が報告されている。スライドの学校名は過去の指定・使用を含み、同一年度の一覧ではない。

3枚目の図は、CPU内部の回路を組み立てる学習から、CPUと周辺回路をつなぐ学習、さらに描画・表示を追加する本研究へと、設計する範囲が広がる関係を示す。簡略図の線は機能のつながりを表し、完全な信号配線や実行順序を表すものではない。

本研究が提供するのは、Wallyに描画機能を追加してゲームを動かす具体例である。CPU設計を学んだ人が、周辺回路の追加へ進むときに、接続コード、プログラム、実機の動作を参照できる。

**質問例：教科書が使われていることと、この研究の価値はどうつながるのか。**

> 教科書の採用例は、CPU設計を学ぶ人がいることを示す背景です。本研究は、その先でWallyを拡張したい人に、描画回路の接続と動作するプログラムの例を提供します。

対応するスライド：3。学校名・授業・年度の詳しい一覧は回答用15・16にある。

出典：[学校別の教科書・教材指定と年度](DDCA授業利用の出典.md)、[SoC設計の教科書の指定・使用例](RVSOC教科書採用の出典.md)、[広島大学シラバス](https://momiji.hiroshima-u.ac.jp/syllabusHtml/2026_12_K6406020.html)、[Harvey Mudd College E154](https://pages.hmc.edu/harris/class/e154/)、[RISC-V学習資料の学習経路](https://github.com/riscv/learn#-learning-paths)。

## 4. SDカードのゲームを読み込んで実行する

SDカードに保存するのは、CPUが実行できる機械語のゲームプログラムである。最初に読込み側の処理がその内容をDDR3へコピーする。その後、CPUの実行先をコピーしたプログラムの開始位置へ移すと、ゲームの命令が実行される。SDカードの中で命令を実行するのではなく、DDR3へ読み込んだ命令をCPUが実行する。

5枚目の左側は、この読込みと分岐をまとめた概念例である。`s0`はSD制御の受信口、`s1`はDDR3の書込み先、`s2`は読込みを終える位置を保持する。

```asm
li   s0,0x1304C       # SD制御の受信口
li   s1,0x80000000    # DDR3の先頭
li   s2,0x80001000    # 読込み終端の例
copy:
lbu  t0,0(s0)        # 受信済みの1バイトを読む
sb   t0,0(s1)        # DDR3へ保存する
addi s1,s1,1         # 保存先を1バイト進める
bltu s1,s2,copy      # 終端未満なら繰り返す
li   t0,0x80000000    # 実行を始める位置
jr   t0              # その位置へ分岐する
```

`lbu`は1バイトの読出し、`sb`は1バイトの書込みである。受信口のアドレスは固定したまま、保存先だけを進める。例では4096バイトをコピーする。`jr t0`はCPUの命令の読出し位置を`t0`の値へ変える。`jr`は`jalr x0,0(t0)`の疑似命令であり、定数を用意する`li`も場合によって複数の実命令へ展開される。

右側は、DDR3へコピーされたゲームをアセンブリで表した概念例である。ゲームの計算と描画命令列の準備を行い、描画命令の1語を接続回路の送信口へ書く。

```asm
game:                 # この例ではDDR3の先頭
...                   # ゲームの計算
...                   # 既存ライブラリで描画命令列を用意
li   t0,0x10080000    # 描画命令を送るアドレス
lw   t1,0(a0)        # 描画命令列の先頭から1語を読む
sw   t1,0(t0)        # 接続回路へ送る
...                   # 残りの命令送信や次のゲーム処理
```

`a0`は描画命令列の先頭アドレスを保持しているものとする。`lw`は32ビットの読出し、`sw`は32ビットの書込みである。CPUが実行するRISC-V命令と、そのCPUが送る描画回路用の命令は、それぞれ受け取る回路が異なる。上の`sw`はCPUの命令で、`t1`の数値が描画回路へ送る命令の1語である。

これらは操作の対応を示す概念的な断片であり、実機のコードを逆アセンブルしたものでも、単独で動く完全なローダーでもない。読込み側には既存のブートローダーやOSを利用している。実際のSDの初期化、読出し要求、転送を進める送信、受信待ち、ファイルや領域の選択、配置、エラー確認、実行環境の準備は省略した。SD制御の受信口を読むだけでは通信は進まない。DDR3の開始位置と4096バイトは説明用の例であり、実機のゲームのサイズ・配置を示す値ではない。命令フェッチの同期やアドレスの対応づけ、描画命令列の終端・順序制御なども実際の実装では扱う。`...`は説明上の省略で、アセンブラの命令ではない。

**質問例：SDカード内のプログラムが描画回路を直接動かすのか。**

> SDカードの内容をDDR3へ読み込み、その命令をCPUが実行します。そのプログラムが描画命令を用意し、決められたアドレスへ書くことで描画回路に送ります。

**質問例：読込み処理も新しく作ったのか。**

> 読込みや実行環境の準備には既存の仕組みを使っています。本研究では、ブロック崩しと、描画回路へ命令を送受信するWally用の接続部分を追加しました。

対応するスライド：5。SDの受信口とコピーは[spi.h](../../console/fpga/zsbl/spi.h)・[boot.c](../../console/fpga/zsbl/boot.c)、描画命令の送信は[WallyBusConnector.hpp](../../console/examples/rasterix/WallyBusConnector.hpp)と[接続回路](../../console/fpga/src/rasterix_apb.sv)に対応する。

## 5. SDカード、CPU、DDR3、描画回路の役割

SDカードにはプログラムを保存しておく。CPUはSD制御を通して内容を読み込み、DDR制御を通してDDR3に保存する。実機ではブートローダーやOSがこの読み込みと配置を担当する。

CPUはDDR3上のゲームプログラムを実行し、ボールの位置、当たり判定、得点などを計算する。その結果を描くため、付属ライブラリを使って描画命令を用意し、描画回路へ送る。

描画回路は命令に従って画像を作る。画像はDDR3へ保存し、表示回路が読み出してHDMI端子へ映像を出す。

**質問例：ゲームの当たり判定も描画回路が行うのか。**

> 当たり判定や得点の計算はCPUが行います。描画回路は、CPUから指定された図形や文字を画像にします。

対応するスライド：6〜8・10・11。

## 6. 接続回路で解決したこと

接続には二つの役割がある。

- **受渡しの形式を合わせる。** CPU側の書込みを受け取り、描画回路側の信号のやり取りに合わせて同じデータを渡す。この部分の回路を追加した。
- **異なるクロック間で渡す。** クロックは回路がデータを扱うタイミングを決める信号である。CPU側と描画側は異なるクロックで動くので、その境界でデータを受け渡すAMD製IPを組み込んだ。

命令の内容を別の命令へ翻訳する、という意味ではない。描画回路用の命令はCPU上のライブラリが用意し、接続回路はその値を受け渡す。

**質問例：二つともAMD製なのか。**

> 形式に合わせる部分は追加した回路です。クロック間の受渡しにはAMD製の回路を使っています。

**質問例：周波数が違うと何が困るのか。**

> 送る側が値を切り替えるタイミングと、受け取る側が値を読むタイミングがそろいません。そのままではデータを正しく渡せない可能性があるので、クロック間の受渡し用IPを使いました。

詳しい仕様では、CPU側はAPB、描画回路側はAXI4-Stream、標準の動作周波数はそれぞれ20 MHzと100 MHzである。非同期FIFOの内部設計や他方式との性能比較は、本編の主張に含めていない。

対応するスライド：9。

## 7. 実機で何を確認したか

30秒の動画で、図形と文字の表示、ボールとパドルの移動、ブロック消去、得点更新を確認した。この構成で、CPUが実行するゲームの処理と、描画・表示が連携して動くことを示す。

パドルは自動操作である。ゲームコントローラは今後の候補に含める。録画のフレームレートをゲームの描画FPSとして報告しない。

**質問例：この動画から何が言えるのか。**

> 接続した構成で、ブロック崩しのゲーム処理と画面の更新が動くことを確認できます。長時間の安定性や、あらゆるゲームの動作までをこの動画で示しているわけではありません。

対応するスライド：12。根拠は[実機記録](../../experiments/dvi-recovery-20261109/README.md)にある。

## 9. FPGA使用量から分かること

回答用18枚目は、「Wally基本構成」と「ゲーム機構成」の二列で比較する。前者は描画機能を追加する前に保存したCPU・周辺回路の構成であり、LUTは36.22%、Block RAMは23.01%だった。ゲーム機ではそれぞれ49.90%、58.90%となる。どちらもCPU単体の使用量ではなく、メモリ制御などを含む全体の値である。


使用率は、その種類の資源がFPGAに何個あり、そのうち何個を使ったかを表す。例えば、LUTは134,600個のうち67,166個を使い、49.90%となる。LUTは論理演算や条件判定を実現する。Block RAMはFPGAチップ内のメモリで、215 / 365 = 58.90%を使う。ボード上のDDR3はこの割合に含めない。

今回の値は、CPU、描画、表示、メモリ制御などを含む回路全体について、配置配線した後のレポートから取り出した。回路設定データのハッシュを確認し、実機動画で使ったものと一致させた。これにより、ゲーム機の回路が対象FPGAに収まる規模であり、その構成でゲームが動いたことを説明できる。

**質問例：使用率が100%未満なら、それだけで動くのか。**

> 使用数だけでは動作は決まりません。今回の回路では配置配線とタイミングを確認したうえで、実機でゲームを動かしています。使用量の表は、その実装に必要だった規模を示しています。

**質問例：余っている資源で何を追加できるのか。**

> 未使用の資源はありますが、追加できる内容は回路の種類や配置にも依存します。コントローラやGUIなどの拡張時には、変更後の使用量とタイミングを確認します。

**質問例：基本構成とゲーム機構成の差がRasterIXの使用量なのか。**

> 回答用18枚目は、保存していたCPU構成とゲーム機構成の全体を比べたものです。その間にほかの回路も変更されているため、差のすべてをRasterIXの使用量とはしていません。

対応するスライド：18。[レポートと動画の対応、数値、比較範囲](../../experiments/standard-display-resources-20261110/README.md)を参照できる。

## 10. まとめの図の階層

一番外側はNexys VideoというFPGAボードである。ボードの中にFPGAチップがあり、その内側にCPUや描画回路を実装する。SDスロット、DDR3メモリ、HDMI端子はチップの外にある部品なので、チップの枠の外、ボードの枠の内側に置いている。

破線で囲む「Wallyリポジトリ」「RasterIXリポジトリ」は、回路コードをどこから取得したかを示す。ボードやチップのような物理的な境界を表すものではない。青い接続回路が、本研究で追加した接続部分である。

対応するスライド：13。
