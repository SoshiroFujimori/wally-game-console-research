# 発表の要点

[スライドと発表原稿](中間発表_主要事項.md) / [技術付録](../thesis/技術付録.md)

この発表の中心は、**既存のCPUと描画回路をつなぐ接続を実装し、ブロック崩しの動作を実機で確認したこと**である。接続方法を、Wallyの学習者が参照できる拡張例として公開する。

## 1. FPGAとCPUの関係

FPGAは、デジタル回路を実装できるチップである。今回は、その中にCPU、SD制御、描画回路などを実装した。CPUもFPGAの中に作った回路の一つである。

ゲームのプログラムは、そのCPUが実行する。回路を記述するHDLと、ゲームを進めるプログラムは、作る対象が異なる。

**質問例：なぜFPGAを使ったのか。**

> CPUと描画回路の接続を、回路として変更できるからです。今回の目的はWallyに周辺回路を加える拡張例を示すことなので、既存の回路コードを組み合わせて実装できるFPGAを使いました。

対応するスライド：2。

## 2. 教科書とのつながりと目的

DDCAは論理回路からCPUの仕組みを学ぶ教科書であり、広島大学の2026年度の授業などで教科書に指定されている。RVSOCは、その基礎を発展させてWallyの設計を学ぶ本であり、Harvey Mudd Collegeの2026年春の授業で教科書として掲載されている。

本研究が提供するのは、Wallyに描画機能を追加してゲームを動かす具体例である。CPU設計を学んだ人が、周辺回路の追加へ進むときに、接続コード、プログラム、実機の動作を参照できる。

**質問例：教科書が使われていることと、この研究の価値はどうつながるのか。**

> 教科書の採用例は、CPU設計を学ぶ人がいることを示す背景です。本研究は、その先でWallyを拡張したい人に、描画回路の接続と動作するプログラムの例を提供します。

対応するスライド：3。学校名・授業・年度の詳しい一覧は回答用15・16にある。

出典：[広島大学シラバス](https://momiji.hiroshima-u.ac.jp/syllabusHtml/2026_12_K6406020.html)、[Harvey Mudd College E154](https://pages.hmc.edu/harris/class/e154/)、[RISC-V学習資料の学習経路](https://github.com/riscv/learn#-learning-paths)。

## 3. 何を利用し、何を追加したか

| 利用したもの | 本研究で行ったこと |
| --- | --- |
| WallyのCPU・SD制御など | 描画回路の接続先を追加し、Nexys Video上の構成に組み込んだ |
| AMD製のDDR制御やクロック間の受渡しのIP | 必要な設定を行い、各回路へ接続した |
| RasterIXの描画・表示本体と付属ライブラリ | Wally側の接続部分と組み合わせ、ゲームから利用した |

ブロック崩しのプログラムも用意した。CPUやRasterIXの本体を新しく設計したという主張ではない。提供元と追加した部分を区別して説明する。

**質問例：既存のものを組み合わせただけなのか。**

> 本体には既存回路を使っています。そのまま一緒に置くだけでは命令を受け渡せないため、受渡しの形式やクロックに対応する接続を実装・構成しました。その接続とゲームの動作結果を、コードと記録で示しています。

対応するスライド：4・8。

## 4. SDカード、CPU、DDR3、描画回路の役割

SDカードにはプログラムを保存しておく。CPUはSD制御を通して内容を読み込み、DDR制御を通してDDR3に保存する。実機ではブートローダーやOSがこの読み込みと配置を担当する。

CPUはDDR3上のゲームプログラムを実行し、ボールの位置、当たり判定、得点などを計算する。その結果を描くため、付属ライブラリを使って描画命令を用意し、描画回路へ送る。

描画回路は命令に従って画像を作る。画像はDDR3へ保存し、表示回路が読み出してHDMI端子へ映像を出す。

**質問例：ゲームの当たり判定も描画回路が行うのか。**

> 当たり判定や得点の計算はCPUが行います。描画回路は、CPUから指定された図形や文字を画像にします。

対応するスライド：5〜7・9・10。

## 5. 接続回路で解決したこと

接続には二つの役割がある。

- **受渡しの形式を合わせる。** CPU側の書込みを受け取り、描画回路側の信号のやり取りに合わせて同じデータを渡す。この部分の回路を追加した。
- **異なるクロック間で渡す。** クロックは回路がデータを扱うタイミングを決める信号である。CPU側と描画側は異なるクロックで動くので、その境界でデータを受け渡すAMD製IPを組み込んだ。

命令の内容を別の命令へ翻訳する、という意味ではない。描画回路用の命令はCPU上のライブラリが用意し、接続回路はその値を受け渡す。

**質問例：二つともAMD製なのか。**

> 形式に合わせる部分は追加した回路です。クロック間の受渡しにはAMD製の回路を使っています。

**質問例：周波数が違うと何が困るのか。**

> 送る側が値を切り替えるタイミングと、受け取る側が値を読むタイミングがそろいません。そのままではデータを正しく渡せない可能性があるので、クロック間の受渡し用IPを使いました。

詳しい仕様では、CPU側はAPB、描画回路側はAXI4-Stream、標準の動作周波数はそれぞれ20 MHzと100 MHzである。非同期FIFOの内部設計や他方式との性能比較は、本編の主張に含めていない。

対応するスライド：8。

## 6. 実機で何を確認したか

30秒の動画で、図形と文字の表示、ボールとパドルの移動、ブロック消去、得点更新を確認した。この構成で、CPUが実行するゲームの処理と、描画・表示が連携して動くことを示す。

パドルは自動操作である。ゲームコントローラは今後の候補に含める。録画のフレームレートをゲームの描画FPSとして報告しない。

**質問例：この動画から何が言えるのか。**

> 接続した構成で、ブロック崩しのゲーム処理と画面の更新が動くことを確認できます。長時間の安定性や、あらゆるゲームの動作までをこの動画で示しているわけではありません。

対応するスライド：11。根拠は[実機記録](../../experiments/dvi-recovery-20261109/README.md)にある。

Wallyに周辺回路を追加したい人に向けて、接続コード、ゲームプログラム、説明、実行手順、実機記録を公開した。必要な変更箇所と、その構成で確認した動作を参照できる。

**質問例：この研究は何に役立つのか。**

> Wallyの学習者が描画回路などを追加するときに、回路をどうつなぎ、どのように動作を確認したかを参照できる設計例になります。実装と実行手順、動作記録を公開しています。

**質問例：教育効果を確認したのか。**

> 今回確認したのはゲーム機としての動作です。学習者の理解度や学習時間への効果は、まだ測定していません。

対応するスライド：3・13。

## 8. FPGA使用量から分かること

使用率は、その種類の資源がFPGAに何個あり、そのうち何個を使ったかを表す。例えば、LUTは134,600個のうち67,166個を使い、49.90%となる。LUTは論理演算や条件判定を実現する。Block RAMはFPGAチップ内のメモリで、215 / 365 = 58.90%を使う。ボード上のDDR3はこの割合に含めない。

今回の値は、CPU、描画、表示、メモリ制御などを含む回路全体について、配置配線した後のレポートから取り出した。回路設定データのハッシュを確認し、実機動画で使ったものと一致させた。これにより、ゲーム機の回路が対象FPGAに収まる規模であり、その構成でゲームが動いたことを説明できる。

**質問例：使用率が100%未満なら、それだけで動くのか。**

> 使用数だけでは動作は決まりません。今回の回路では配置配線とタイミングを確認したうえで、実機でゲームを動かしています。使用量の表は、その実装に必要だった規模を示しています。

**質問例：余っている資源で何を追加できるのか。**

> 未使用の資源はありますが、追加できる内容は回路の種類や配置にも依存します。コントローラやGUIなどの拡張時には、変更後の使用量とタイミングを確認します。

**質問例：BeforeとAfterの差がRasterIXの使用量なのか。**

> 回答用18は、保存していたCPU構成とゲーム機構成の全体を比べたものです。その間にほかの回路も変更されているため、差のすべてをRasterIXの使用量とはしていません。

対応するスライド：12・18。[レポートと動画の対応、数値、比較範囲](../../experiments/standard-display-resources-20261110/README.md)を参照できる。
