用語を覚える際は、実物のどこを指し、その前後に何がつながるかも確認する。次の表は語の定義だけでなく、このゲーム機での役割を示す。例えばCPU、SoC、FPGAボードは同じ範囲の別名ではない。

<a id="s_d_1"></a>
## 68.1 回路とソフトウェアの用語

| 用語 | 本研究での具体的な意味 |
|---|---|
| FPGA | 回路のつながりを設定できるチップ |
| Nexys Video | FPGAとメモリ、端子などを載せた基板 |
| Wally | FPGA内でLinuxとゲームを実行するCPUを含む公開設計 |
| RISC-V | CPUが解釈する命令の約束 |
| RasterIX | 図形の指定から画素を作る公開設計とライブラリ |
| RTL | 信号と記憶素子の動きを表す回路の記述 |
| IP | 生成して組み込める既存の回路部品 |
| Tcl | Vivadoなどへ処理を指示する言語 |
| XDC | 端子や時間条件を記す制約ファイル |
| デバイスツリー | 実機のメモリや周辺機器をLinuxへ伝えるデータ |
| MMIO | 特定の番地の読み書きで回路を操作する方法 |
| FIFO | 先に入れたデータから順に取り出す待ち行列 |
| CDC | 異なるクロックで動く回路同士の境界 |
| バックプレッシャー | 受け取れない側が、送り手を待たせること |

<a id="s_d_2"></a>
## 68.2 画像に関する用語

| 用語 | 何を入れる場所・処理か | 今回の具体例 |
|---|---|---|
| 頂点 | 図形の角の位置 | 四角形の四つの角 |
| テクスチャ | 図形に貼る画像 | 文字の模様 |
| コマンドバッファ | 回路へ渡す命令列 | 帯ごとに準備するリスト |
| 内部作業領域 | 描画途中の画素 | 65,536画素分の内部メモリ |
| フレームバッファ | 表示画像の画素列 | DDR3内の614,400 byte |
| フロントバッファ | いま表示に使う画像 | 二枚のうち表示側の役割 |
| バックバッファ | 次の画像を描く側 | 二枚のうち描画側の役割 |
| ラスタライズ | 図形から塗る画素を決める | 三角形の内側を塗る |
| RGB565 | 2 byteで色を表す形式 | 赤5、緑6、青5 bit |
| 部分描画 | 変化した範囲を描き直す | 古いボールを消して新しい位置を描く |

<a id="s_d_3"></a>
## 68.3 理解を確かめる小さな課題

「ボールのxを100から103へ変えたとき、どこが変わるか」を説明してみる。まずGameの位置が変わり、sceneの四角形の位置が変わり、Rendererが違う頂点を渡し、命令と画素が変わる。最後に表示回路が新しい画像を読む。この順を自分の言葉で追えれば、ゲームの変数と映像がつながる。

次に、「命令FIFOが満杯なら何が起こるか」を説明する。CPU側の書き込みが待ち、空きができたときに同じデータが一度受け取られる。書き込み完了と表示完了は異なる。ここまで言えれば、命令の接続と画面切り替えを区別できている。

最後に、「速くなった結果が正しいと言うには何を比べるか」を説明する。同じゲーム状態、同じ最終画素、同じハードウェア条件を確かめ、その上で時間を比べる。単に数字が大きい、映像が滑らかという印象だけで判断しない理由が分かれば、実験の説明へ進める。
