# 公開資料の更新と個人情報の扱い

このリポジトリには、研究資料の公開用コピーを保存します。元の非公開資料には手を加えません。
氏名、指導教員名、所属、学籍情報、本人のメールアドレス、ユーザー名を含むパス、
ホスト名、対象機器のシリアル番号を公開用の表記へ置き換えます。
文書の作成者・最終編集者・コメント・変更履歴・カスタムXML・サムネイルも除去します。

## 名前のリスト自体を公開しない

実名と置換文字列は `.private/redactions.json` に置きます。
このディレクトリはGitの対象外です。実名のハッシュ一覧も公開しません。
未設定のまま匿名化やローカル公開前検査を実行すると、処理を停止します。

設定の書式は次のとおりです。実際の値を公開ファイルへ書いてはいけません。

```json
{
  "version": 1,
  "replacements": {"PRIVATE_TERM": "公開用の表記"},
  "private_terms": ["PRIVATE_TERM"]
}
```

氏名の空白の有無・表記違い・ローマ字・所属名も登録します。
既存の公開リポジトリの所有者名や明示的なGitHub URLは、公開が認められた参照です。
上流ソースの他の著者の著作権表示は、そのまま保持します。

## 公開用コピーを作る

```bash
.venv/bin/python tools/publication/sanitize.py \
  /path/to/private/document.docx build/document.docx \
  --config .private/redactions.json
```

このツールは入力ファイルを上書きしません。置換は本文だけでなく、OOXMLの
複数の文字列に分割された氏名、JSONのUnicode表記、URLの符号化にも対応します。
ZIP内のファイルも調べます。対応していないバイナリは自動で通しません。
PDFの本文に個人情報が残っている場合は自動出力を止めます。

最初のインポート時に使った選択リストは `.private/imports.json` にあります。
このリストには元の保存場所が含まれるため公開しません。
元資料を改訂した場合は `import_local.py --check` で変更対象を調べ、
`import_local.py --export` で新しいコピーを `build/import/` に作ります。
公開済みファイルを自動的に上書き・コミット・プッシュすることはありません。
元資料のWindowsパスを登録している場合は、WindowsのPythonでこのインポートを実行します。
Wordで開いている原稿も、保存済みの内容を共有読み取りします。未保存の編集内容は取り込みません。
この比較には、匿名化後に行った参照先や文書構成の調整による差分も含まれます。
そのため、出力を確認してから必要な変更だけを公開側へ反映します。

## 画像と動画

画像に描かれた文字や人物は、本文の文字検索だけでは確認できません。
画像はメタデータを除去し、内容を目視確認してから、そのSHA-256を
`publication/media-review.json` に記録します。画像が変わると検査は停止します。
Word内部の画像、PDF、動画もこの対象です。
公開動画はゲーム画面を確認し、音声・個人メタデータ・チャプターを除去したものです。
新規メディアを自動で「確認済み」にしてはいけません。

## 履歴に入る前に止める

`.githooks/pre-commit` はステージ済みの内容を検査します。
`.githooks/pre-push` は送信対象の全コミットを検査します。
作業ツリーの最新ファイルだけを直しても、過去の送信対象コミットに残っていれば停止します。
検査結果には検出した個人情報そのものを表示しません。

GitHub Actionsは一般的なパス・メール・資格情報・文書構造・未確認メディアを検査します。
公開しない実名のリストは利用できないため、ローカル検査を置き換えるものではありません。
公開後に消しても、他の人が取得したコピーまでは消せません。そのため公開前の検査を行います。

## 実験データとしての扱い

測定値、試行条件、ソースコミット、成功・失敗の記録は維持します。
パスや識別情報を置き換えたログは、原本とバイト単位で同一ではありません。
公開版の内容は `publication/files.json` のハッシュで確認します。
過去の実験記録中のハッシュは、当時のソースや非公開原本を指す場合があります。

公開する変更をステージした後、`tools/publication/manifest.py --write` で公開版の記録を更新し、
`publication/files.json` もステージします。記録するのはGitの改行変換後の内容です。
`manifest.py --check` で、その記録とステージ済みの内容が一致するか確認できます。
