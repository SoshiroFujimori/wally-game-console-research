# Board-based presentation variant

This alternative retains the canonical deck. Its public output and narration
are in [the presentation directory](../../../docs/presentation/board-evolution/中間発表_ボード図を拡張する案.md).

## Diagram structure

Slide 2 identifies the FPGA beneath the black heat sink in the enlarged Nexys
Video photograph. The accompanying AND gate and SystemVerilog describe the
same small circuit example, not a gate that controls the external peripherals.
The SD slot is on the underside. Schematic positions are not physical placement.

Slide 3 enlarges the chip-only view by 1.2x and explains `lw` with instruction
and data memories inside the FPGA. Slide 4 returns to the whole board, adds the
bus and AMD DDR controller, and follows the same load using external DDR3.
Slide 5 adds PC+4 and explains `sw` using that DDR3 connection. Slides 6-8 add
SD control, RasterIX and display. `BOARD` in `board-circuit.mjs` preserves the
datapath relationships and fixed whole-board positions across slides 4-8.
CPU-wide white enclosures and captions are absent. Gray paths are inactive or
outside the current explanation. Worked addresses are teaching examples.

The MIG generator is `console/fpga/generator/ddr3-nexysvideo.tcl`. Its internals
are omitted; clocks, pins, resets and interface requirements still apply.
The sender adapter is grouped into RasterIX in the main slides. Cache and MMU
internals, framebuffer internals and arbitration remain appendix topics.

The hidden question slide is an editable expansion of the RVSOC Figure 7.11
pipeline, generated by `wally-overview.mjs` from the existing RVSOC-derived
diagram. It keeps the PC, register file, ALU, full stage boundaries, operand
selectors and lower writeback/forwarding paths. IROM/DTIM are replaced by the
configured MMU/cache/bus-interface paths. EBU, uncore, memory IP and graphics
extend that datapath; the diagram does not rearrange the CPU into a new list
of functional boxes. Readable module labels replace the previous tiny internal
gate schematics. It is not an exhaustive or cycle-accurate RTL/netlist drawing.
The separate command and response FIFOs show their transfer directions.
The more detailed gate drawings remain in `../wally-circuit.mjs` for future
module-specific slides. Source and omission notes are in the speaker notes.

## Embedded demonstration

Slide 9 embeds the existing, reviewed 30-second E6 recording without transcoding:
`docs/thesis/再現資料/実験記録/E6/report/results/video/breakout-latest-30s.mp4`.
The existing first verified frame is its poster. Click the video in a slideshow
to play it. No external file is needed by the delivered PowerPoint. Markdown
links to the same recording. The footage is deterministic autoplay, not manual
controller input. Recorded video rate is not a game-FPS measurement.

`embed_video.py` adds standard Office video relationships and click-to-play
timing to the Artifact Tool picture. The local authoring API has no video
insertion operation. For public builds, text, notes and image metadata are
sanitized before attaching the video. The helper rejects an MP4 whose exact
hash is absent from the existing media-review record. The final publication
audit checks all document XML and the embedded media hash. The repository
sanitizer and hooks are not relaxed. The package retains a poster for static
previews; static rendering is not a native PowerPoint playback test.

The main-talk allocation is 355 seconds including 30 seconds of video. Explain
the result while it plays. This is a plan, not a timed rehearsal. The hidden
question slide is excluded from the main allocation. Existing E6 results and
their scope are unchanged.

## Build

Use the bundled Artifact Tool environment described in the canonical README.
Run `build.mjs RESEARCH_ROOT PRIVATE_BUILD_DIRECTORY` with this entry point.
It produces the editable PPTX, Markdown, PNG previews and private validation
records. Private cover input stays outside the repository. Review final slides
and embedded media, run the local privacy audit, and import only the selected
public outputs. Do not import private cover data or build records.
