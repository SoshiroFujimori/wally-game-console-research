# DVI標準表示構成の確認

2026年11月8日。本稿の「標準」は製品既定の構成を意味し、DVI規格適合認証を意味しない。

発表の機能図は、描画回路（RasterIX）から独立した「表示回路」の箱として表せる。実演結果の説明は次の範囲が正確である。

> FPGA上にCPU・描画回路・表示回路を構成し、ブロック崩しの移動・反射・ブロック消去を実機映像で確認した。

この表現なら、本文・読み上げでOBSや伝送方式を説明する必要はなく、「試験用HDMI回路」という脚注を本文から外して、使用構成・確認条件を再現記録へまとめられる。ただし、図や説明に「製品標準構成で動作確認」「RasterIX付属の表示回路で撮影」と書くことはできない。現在の実演動画はE8の表示回路で取得している。実装の出典は、描画が公式RasterIX、表示が研究用scanoutとhdl-util/hdmiであり、表示までRasterIX本体の成果として囲まない。

## 実装の差

| 項目 | 製品標準DVI構成 | E8・現在の実演動画 |
|---|---|---|
| CPU・GPU | Wally 20 MHz・公式RasterIX 100 MHz | 同じCPU/GPUのRTL・設定 |
| 描画画像 | 640×480・RGB565 | 同じ |
| 表示画像 | 640×480を送出 | 1280×720のうち960×720へ縦横1.5倍、左右160画素の黒帯 |
| DDR読出し | RasterIXに同梱されたultraembedded core_dvi_framebufferのFIFO | 研究用の二つの行バッファ、1行10回の32beat AXI読出し |
| 画像切替の完了条件 | 新しいベースアドレスの最初のburstが返るまで待つ | 垂直帰線の開始・旧読出し完了を待ち、新しい先頭行の完了後に返す |
| 映像の符号化・送出 | 同梱DVIコア | hdl-util/hdmi、DVI_OUTPUT=0、VIDEO_ID_CODE=4 |
| 表示クロック要求 | 25.2 / 126 MHz | 74.25 / 371.25 MHz |
| 制御接続 | 製品のCPU→RasterIX命令経路 | 変更なし |

E8の差分対象は`rasterixdisplay.sv`、`videoclock.tcl`、`rasterixmem.tcl`、`constraints-rasterixdisplay.xdc`、`wally.tcl`の5ファイル。送出形式だけを切り替えた比較ではなく、メモリ読出し・画像切替・クロック・送信器をまとめて変更している。したがって、映像の取得成功を特定の信号一つの効果と解釈しない。

標準DVIの固定版RTLには、横カウンタ0〜800、縦0〜525という両端を含む条件があり、総数は801×526になる。同期は正極性のままDVIエンコーダへ渡る。25.2 MHzから計算した約59.811 Hzはソースからの計算値であり、物理波形の測定値ではない。過去には800×525や別極性の診断回路も不成功だったため、この差だけを原因や修正方法と断定しない。

## ソースと既存証拠の確認

- 標準bitstreamの凍結ソースマニフェスト995ファイルと現在の製品ed6a1c09を照合し、994ファイルが一致した。差は`examples/rasterix/Breakout.hpp`のみで、CPU・GPU接続・表示を含むRTL/設定の差はなかった。E8の基準261832d4から現行製品へのGit差分も同じ1ファイルだけである。
- 公式RasterIXは`9269a01c9bd4c3342bfa70ef8e3cdd751c15c6d0`。E8の変更後5ファイルは保存されたSHA256すべてと一致した。E8既存記録の検査も32ハッシュ・4実行結果の整合性を確認した。これらはソース/記録検査で、実機試験の代替ではない。
- 2026年10月8日のE6には標準構成の30秒映像がある。記録では全1,801復号フレームに枠を検出し、ボール位置の変化を調べた。11月8日の別の標準構成診断ではboot2/4にゲーム映像、boot1/3/5/6には形式エラーまたは黒画面が記録されている。今回boot2の原動画のハッシュと10秒時点の実際のゲーム画像を再確認した。これらの旧ゲーム実行ファイルはE8基本動作試験と同じ`e8fa6130...`である。
- 6起動・8実行は受信操作などが異なる診断履歴であり、成功率や互換確率の推定に使わない。「DVI新規認識0/4、HDMI4/4」は2026年9月の同一診断回路での別実験であり、標準製品の起動回数でも、一般のモニターの成功率でもない。
- ultraembeddedのREADMEには別ボードとDellモニター/LGテレビでの試験実績がある。これはDVI出力方式の利用実績であり、このNexys Videoのbitstreamが別の表示機器でも動くという実機証拠にはならない。

## 今回の有界実機試験

最新タイトル版の標準構成実機記録がない点だけを埋めるため、既存の選択済みNexys Videoに標準bitstreamを1回設定し、最新の同一実行ファイルを30秒実行。その後、確認済みE8へ戻して同じ試験を行った。受信機の再起動、試験パターンの挿入、SD切替、CPU周波数変更、マウス/キーボード操作は行っていない。SDは読み取り専用でロード後にアンマウントし、実機上の実行ファイルSHA256を照合した。

| 構成 | ゲーム実行 | 映像 |
|---|---|---|
| 製品標準DVI | 30.011秒、score=170、lives=3、終了0 | 2,191復号フレーム中、ゲーム検出0。取得画像は形式エラー |
| E8へ復旧 | 30.000秒、score=170、lives=3、終了0 | 1,981ゲーム出現後フレームすべてで枠・805か所の固定文字検査に合格。選択画像でゲーム表示を確認 |

試験の順序は標準→E8復旧の各1回で、無作為化した反復比較ではない。現在の接続先での観察結果であり、原因の単独特定、他の表示機器、冷間電源投入、電気的な規格適合は確認していない。CPU/GPUのソースと入力プログラムは共通だが、表示経路がメモリ負荷や待ち時間を変えるため、実行時の全タイミングが同一とは主張しない。

## 現在の環境で確認できる範囲

Windowsの稼働中OBS内部APIからFPGA入力だけの画像・動画を取り出し、UARTで起動・実行・ハッシュを確認できた。これには画面の前面化や手動操作は必要なかった。現在の接続で標準DVIが受信されるかは試せるが、接続されていない一般モニターとの相性はこのAPIでは検証できない。今回の確認から「別のモニターなら非常に高い確率で動く」とは言えない。

標準構成の過去の成功は残す。今回の失敗も残し、現在のE8動画を標準構成の動画へ読み替えない。発表の中心は本研究の実機構成で観察したゲーム動作とし、表示実装の識別情報と未確認範囲を再現記録に置くことを推奨する。
